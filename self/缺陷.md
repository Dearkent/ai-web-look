# 缺陷清单（我犯过的错，以及怎么防）

格式：现象 → 根因 → 对应经验卡片 → 是否已固化成检查。
目标不是不犯错，而是同一类错不犯第二次。

### D01 许可证只看根目录，漏掉子包的不同许可
- 现象：Theatre.js 先写成 Apache-2.0，实际编辑器 `packages/studio` 是 AGPL-3.0。
- 根因：只读了仓库根目录的 LICENSE。
- 经验：L001 ；固化：checks/license_scan.py

### D02 心算计数出错
- 现象：停更仓库写成 17 个（实为 16）；“前六个”实为七个；“7 个平台里 6 个用 AI SDK”实为 9 个里 7 个。
- 根因：数字靠扫一眼得出，没有用代码数。
- 经验：L002 ；固化：checks/count_check.py

### D03 文档里用文字查找改表格，跨单元格失败
- 现象：`find` 一段跨越多个单元格的文字，返回 find_none。
- 根因：查找不能跨单元格。
- 经验：L003

### D04 草稿里出现错别字
- 现象：“给用网站”少了“户”字。
- 根因：长段落一次写完没有回读。
- 经验：L009（写完的段落按句回读一遍）

### D06 自己写的检查脚本也会错：MPL 被误判成 AGPL
- 现象：全量重扫时，Lighthouse 内置的 axe 许可（MPL-2.0）被报成 AGPL。
- 根因：MPL 正文提到 AGPL，而规则表先查 AGPL；第一轮读取窗口小，侥幸没暴露。
- 经验：L010 ；固化：规则重新排序 + 评测 E08

### D07 并行批处理静默丢了一个结果
- 现象：157 个仓库只扫出 156 行，openai-agents-js 消失，没有任何报错。
- 根因：高并发下单个任务失败，错误被 `2>/dev/null` 吞掉。
- 经验：L011 ；固化：checks/sweep.sh 自动核对条数并重跑

### D08 大脑的回忆只按字面匹配，漏掉了最相关的经验
- 现象：T06 任务写“运行时报错回读”，最相关的 P006（错误写回对话）连前 8 名都没进；“回读”反而误配了 L009 的“回读一遍”。
- 根因：检索只看字面二元组，不懂“报错=错误”；工作经验和产品经验混在一起排名，互相挤占。
- 改进：brain.py 加同义词组；回忆时 L、P 两类分开各取前 3；评测 E13 防回退。
- 以后：每次发现漏召回，把那组词加进 SYNONYMS，并补一条评测。

### D05 相信项目自称的“开源”
- 现象：Easyblocks 自称开源框架，LICENSE 实为 AGPL-3.0；supermemory 开源部分只有前端和 SDK。
- 根因：没读 LICENSE 文件就采信 README 和第三方介绍。
- 经验：L008

### D09 检查器第一跑“0 错误”就容易当成通过；而它自己就有死循环
- 现象：图纸检查器首跑咖啡馆示例 0 错误；变异测试第 11 项“父页面成环”让面包屑遍历卡死，整条命令超时。
- 根因：只用正例验证检查器；沿 parent 链走的 while 循环没防环——检查器自己犯了它要抓的错。
- 经验：L015 ；固化：product/tools/mutation_test.py（27 种改法）+ 评测 E20

### D10 自己定的格式，写第二、三个示例才暴露表达不了的情况
- 现象：只用咖啡馆一个示例时格式“完美”；写 SaaS 时发现“点外链注册才算完成”的流程写不出来，多语言要求也没人检查。
- 根因：格式只对一种网站做了推演。
- 改进：flows 加 completes_with（S031），新增语言覆盖检查（S034）。以后定任何格式至少用 3 种差异大的样例走一遍。

### D11 我自己的工具也会卡住：三种“停不下来”
- 现象：①检查器面包屑遍历在父子成环时死循环；②在无检出克隆上 `git grep HEAD` 几分钟不结束；③验证门超时只杀 shell，孙子进程握着管道，验证门本身可能一直等。
- 根因：没有把“必须有界”当成写脚本的硬规则。
- 经验：L016 ；固化：checks/loop_audit.py（E27、E28）、brain.run_bounded（E29）

### D12 凭印象对编号、对参数位置
- 现象：记经验使用时写成 P003（实际是 P005）；测试里把改名目标按位置传进了 content 字段；测试数据标签和基线撞名。
- 根因：以为记得，没有查。
- 经验：L017
- 第五轮又犯一次：复读检测测试要求“摘录里含整句”，可重复单元的起点本来就可以在句中——又是测试的预设错了，不是代码错。

### D13 交付前没看界面：检查全过，样子却不对
- 现象：风格预览三列几乎一模一样，占位文字是“【heading待写】”，三列布局没生效；图纸 0 错误、浏览器 0 问题。
- 根因：把“检查通过”当成“能交付”；视觉问题没有任何检查覆盖。
- 经验：L018
- 第七轮再次发生：工作台的风格预览里首屏大标题和“为什么选我们”是空白（出现动画在缩小的预览框里收不到信号，内容一直透明），所有检查都通过；截图才发现。已改成“动画不挡内容”，并新增检查（E43）。

### D14 模块与标准库重名，并且把错误输出丢掉了
- 现象：copy.py 与标准库 copy 冲突，命令失败；我加了 2>/dev/null，一开始看不到原因。
- 经验：L019

### D15 先猜原因、再放宽测试：把问题藏起来而不是解决
- 现象：工作台测试报 404；先猜成时序竞争并改了目录结构（不是原因），再把测试里的“加载失败”过滤掉，测试变绿——问题被掩盖。拆掉网站图标的修复让 404 重现，才确认是浏览器自动请求 /favicon.ico。
- 经验：L020

### D16 冲突归因做反了：坏知识留下、好知识被停用
- 现象：复核第一版按顺序测“其余知识 + 这一条”。注入一条和老知识矛盾的知识后，先被测的两条好知识因为它的存在失败、被停用；最后测它时矛盾对象已经停用，它反而通过。测试当场抓到。
- 经验：L022

### D17 测试样本没有区分力
- 现象：用“猫咖要预约”测“新说法附带的功能会生效”，可咖啡馆默认就有预约，学没学都会通过。改成咖啡馆默认没有的“相册”，并要求标注“学自 K…”。这是把测试改严，不是放宽。
- 经验：L017（靠记忆对上的东西要查）、P016 同类：测试要能失败

### D18 所有检查都漏了：长英文店名在手机上撑破屏幕
- 现象：店名是一个很长的英文单词时，手机 375px 下内容比屏幕宽 150–400px。之前的评测集全是中文店名，从没碰到；同时“回答店名”被截成 16 个字，把问题藏住了。
- 处理：放宽到 40 字；由自我纠错自动修（换行修补），修好后记住病因，并经对照实验推广。

### D19 视觉硬指标从没量过，三类老问题一直在
- 现象：第一次在手机宽度量对比度和点按尺寸，24 个组合几乎全中：导航链接 32×20px；链接用主色，对比度 3.3–4.2:1（主色只保证了 3:1，够按钮不够文字）；大色块家族偶数区块里的卡片继承了浅色文字，卡片标题白底白字（1:1）。
- 处理：链接颜色单独算到 4.5:1；导航和面包屑链接加大到 44px；卡片文字用前景色。检查加进浏览器检查，配做坏样本 badsite3。
- 经验：P026、L023

### D20 检查器误报：指向 index.html 的链接被当成死链
- 现象：做 badsite3 样本时发现，链接写成 index.html 会被报“死链”。生成器从不这么写，所以一直没暴露。检查器本身也要有反例测试。
- 经验：L015（每个错误码都要有反例）

### D21 规则把“给我的咖啡馆做个网站”里的“我的咖啡馆做个网站”当成了目标访客
- 现象：设计模型合并规则时，对照规则版的输出才发现。“给…”后面不一定是访客。
- 处理：以“我/咱”开头、或含“网站/做个/官网”的不算访客。

### D22 导出时中文文件名直接写进 HTTP 头，服务端崩了
- 现象：HTTP 头只能放 ASCII，“巷口咖啡-v1.zip”让请求直接断开。端到端测试抓到。
- 处理：按 RFC 5987 用 filename*=UTF-8'' 编码，另给一个 ASCII 的备用名。

### D23 SEO 老问题：描述太短、内页没有一级标题、标题跳级
- 现象：上线前体检第一次跑就发现。首页描述只有 9 个字；预约、隐私等内页没有 h1；作品页 h1 后直接 h3。
- 处理：每页按用途生成 20 字以上的描述；没有一级标题的页，把第一个区块标题升为一级（一个标题都没有时才加页面标题——先试过一律加页面标题，截图一看“预约 / 预约”重复了）；生成时自动消除标题跳级。经验：P030

### D24 色带区块里的链接对比度不够
- 现象：表单里新加的“《隐私政策》”链接在色带背景上只有 4.2–4.5:1。链接颜色只对页面底色算过。
- 处理：链接颜色同时对底色和同深浅的色带算到 4.5:1；大色块家族的深色带上链接继承文字颜色。styles_test 加了这一项。

### D25 生成器在 Python 3.12 以前根本导入不了
- 现象：generate.py 的 f-string 花括号里有反斜杠，3.9/3.10/3.11 直接 SyntaxError。开发用 3.13，所有测试都是绿的。很多 Mac 自带 3.9，用户一启动就会崩。发布测试第一次用 3.9 跑就抓到。
- 处理：改写；验证门加旧版 Python 解析检查。经验：L025

### D26 依赖 jsonschema 没声明，启动器也不检查
- 现象：全新环境里一生成就报 ModuleNotFoundError。
- 处理：加 requirements.txt；启动器自检这一项，start.sh / start.bat 带 --setup 自动装到用户目录或虚拟环境；提示里的命令带引号（>= 在终端里会被当成重定向）。

### D27 兼容检查的盲区：ast.parse(feature_version=(3,9)) 不管 f-string 细节
- 现象：第一版兼容扫描报“只有 1 个问题”，漏掉了 D25。
- 处理：必须用真的旧解释器解析。经验：L025

### D28 工作台端到端测试偶发失败一次，原因还没定位
- 现象：一次完整验证门里 E42 没输出“70/70 通过”；单独连跑 3 次、再跑一次完整验证门都通过。当时验证门不打印实际输出，看不到是哪一项。
- 处理：验证门失败时打印实际输出的最后几行。再出现时就能看到原因，先不猜（D15 的教训）。

### D29 工作台越堆越长、满屏内部用语
- 现象：生成后要翻 3 屏才看到网站（电脑 4421px、手机 7308px）；“Bakery/Cafe（把握：high）”“P0 预约”“zh-CN”“Standard”、风格英文名、每一步都重复“规则版”。截图一看就发现，功能测试全绿时看不出来。
- 处理：三个标签页；步骤条；生成后前三步收起；网站占主区域；全部改成用户的话。电脑 1372px、手机 2149px。经验：P032

### D30 诊断把被撑宽的图片当成病因
- 现象：关于页加了配图后，长英文店名把左右分栏撑宽，图片跟着变宽；浏览器诊断把图片也算成“超出屏幕的元素”，自我纠错多加了一个没必要的 media-fit 修补（结果没坏，但病因判断错了，会学到错的经验）。
- 处理：图片只有比它的容器还宽时才算病因，和容器一样宽算“被连累”。selflearn 测试里“只加 wrap-long-words”这一项抓到了它。经验：P033

### D31 常见问题把建站时的内部问题放到了网站上
- 现象：生成的“常见问题”区块里出现“网站叫什么名字？默认：暂用‘我的网站’”“预约需要先付定金吗？默认：不收定金，只登记”——这是工作台问店主的问题和默认答案，不是访客会问的；区块也没有标题。测试都过了，是做 UI 参考对比、看手机截图时发现的。
- 处理：常见问题改成按网站功能出访客会问的问题（预约多久、改约、付款、营业时间、怎么过来、怎么联系），答案不能替店家编的一律“待填”；加区块标题；ui_patterns_test 检查不再出现“默认：”和内部问题。经验：P034

### D32 测试和界面异步刷新抢跑（E42 偶尔 84/85）
- 现象：“可以换回示意插图”这一项偶尔失败。界面先显示“换回了示意插图”的提示，图片列表随后才异步刷新；测试看到提示就去读列表，读到的还是旧的“你的照片”。单独跑三次过两次，验证门里失败一次。
- 处理：测试等列表刷新完成（第一行出现“示意插图”）再判断。教训和 L016 一样：等的是“结果出现”，不是“某个提示出现”。D28 那次的偶发失败很可能也是同类，当时没抓到具体是哪一项——验证门现在会打印实际输出，这次靠逐项输出定位到了。

### D33 实况页面“界面大小总在闪烁”（用户报告）
- 现象：用户在 Mac 上看实况页时界面尺寸一直闪。复现：窗口窄于 1100 像素（半屏、claude.ai 侧边栏约 720 像素）时，窄屏布局把放卡片的主区高度压成 0，“列满了就删最老的卡片”立刻把新卡片删掉，卡片一出一没、整页跟着跳；宽屏下底部三块面板按日志文字长短互相挤（482→621→614 像素来回变）。我自己只在 1440×900 截过图，没测过窄窗口和事件不断涌入的情况。
- 处理：网格列一律 minmax(0,…)（内容不撑列）；主区最小高度、窄屏每列固定 330 像素；画布放进 .fig 绝对定位、尺寸用 ResizeObserver（不在每帧里读布局改画布）；数字等宽、标题行不换行；内容没变不重画、日志和指标 250 毫秒合并一次；卡片入场只淡入；列没高度时不删卡片。live_test 加四种窗口尺寸、事件涌入时的尺寸稳定检查（换回旧页面会失败）。另：验证门里测试造的假建站事件记到 runs/events-tests.jsonl，不再混进实况的真实记录，已清掉混进去的 999 条。经验：P039

### D34 用户 Mac 上工作台一启动就崩：设计知识表路径写死在开发机上（用户报告）
- 现象：双击启动后报 FileNotFoundError：/home/claude/repos3/…/styles.csv。understand.py 的 KB_DIR 默认值是我沙盒里那份开源项目副本的绝对路径，5 张设计知识表（风格、配色、字体、行业推荐、落地页顺序）从来没进仓库。发布测试（E55）只在同一台机器的新虚拟环境里跑，那个路径恰好存在，所以一直通过。
- 处理：5 张表连同 MIT 许可证放进 product/kb/uiux（来源.md 记版本），KB_DIR 默认读仓库里的；E55 加两条：压缩包里必须带知识表和许可证、程序代码里不许出现 /home/claude 或 /Users/ 这类开发机路径。另外用真实的 Python 3.9（用户 Mac 自带 3.9.6）、把开发机上那个目录藏起来，走完“启动 → 三个预览 → 选定 → 修改 → 导出”。
- 经验：测“新电脑能不能用”，不能只换虚拟环境，还要拿掉开发机上独有的东西，并用用户的 Python 版本跑。

### D35 藏掉空作品区以后，首屏按钮还指着它（验证门抓到）
- 现象：这一轮让“首页没有照片也没有名称的作品区”不再显示（只剩示意图很难看）。作品集示例的首屏按钮是“看作品 → #work”，区块藏了，链接成了死链，真实浏览器检查报“锚点不存在”（E34 失败）。同一轮“明说的动作优先当主目标”把“了解和下载”的开源页也改成了下载为主，留出集 6/6 掉到 5/6（E39）。
- 处理：区块因为没内容被藏起来以后，所有指向它的链接（按钮、其他页的导航）改指联系区块，没有就指页面顶部；“下载”不参与主目标前移（开源页仍以介绍为主）。两项都回到全过。
- 经验：藏一个区块不只是不画它，还要处理所有指向它的东西。改动后整门跑一遍才发现——单项测试（生成器 16/16）没覆盖到示例里的按钮。
