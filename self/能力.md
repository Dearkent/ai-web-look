# 能力清单（我在这个环境里能做什么、怎么做最好）

每一条都来自实际操作验证过，不是猜测。新发现直接追加，并注明日期和来源任务。

### 读 GitHub 仓库：用 git，不用 gh API
- 本环境 `gh api` 调用失败，但 `git clone` 经代理可用。（2026-11-17）
- 只取元数据：`git clone --depth 1 --filter=blob:none --no-checkout`，再用 `git ls-tree` 看文件、`git show HEAD:路径` 读单个文件。快、省空间，而且不检出任何文件、不执行任何代码。（2026-11-18，157 个仓库约 2 分钟）

### 并行
- 互不依赖的克隆、搜索要并行：`xargs -P 24` 跑元数据脚本。

### 文档（Claude Docs）
- 一个章节一次写入，先放占位块再填充，读者能看着它长出来。
- 画图后用截图读回检查，三张图都一次通过。

### 检索与引用
- WebSearch 结果在后续轮次会被清除，只有当时写进文档或文件的事实能留下来。

### 校验 JSON 图纸
- 本环境已装 jsonschema 4.26（含 referencing），可直接做 2020-12 草案校验和跨文件 `$ref`；不需要额外安装第三方包。（2026-11-18，T11）
- 枚举报错原文会倾倒整张词表，给模型看的报错要改写成“最接近的 3 个合法值”。（T14）

### 长命令
- 测试脚本一律 `timeout N python3 -u`：死循环时能及时停下，输出不被缓冲。（T14，见 D09）

### 无检出克隆的读法（2026-11-18，T16）
- `--filter=blob:none --no-checkout` 的克隆上，`git ls-tree` 和单文件 `git show` 很快；全库 `git grep HEAD` 会逐个下载对象，实测超过 2 分钟未完成，禁止使用。
- checks/cite_check.py 已支持对这种克隆按文件核对事实。
