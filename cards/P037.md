## 根因
- 之前只学过 30 个界面库的笔记，没有“批量喂网站”的通道；用户要它看大量网站来丰富设计。
- 第三方网站和模板是外来代码：直接运行有风险（规矩：只做笔记、不运行）；整页原文进公开仓库也不合适。
- 框架 CSS（Bootstrap 整套）里有几百种颜色和字号，全算进来统计就歪了。
- 第一版区块识别先看“有没有 h1”，咖啡馆模板每段都用 h1，结果全认成首屏、菜单区一个都没认出来。

## 做法
- 标本（specimen.py）：标准库 html.parser 静态解析，<script>/<template>/<svg> 整段跳过；只存颜色值、字号、行高、留白、版心宽、圆角、阴影/渐变/毛玻璃计数、区块类型顺序、导航链接数、首屏字数/按钮数、风格家族、来源。标题和正文只在内存里用来猜行业，用完就丢。
- 只算“页面真用到的”CSS 规则：选择器最后一段的类名、id、标签都出现在页面上才统计；CSS 变量和 SCSS 变量会解开；clamp() 取最大值。Tailwind 类名按官方刻度换算（text-6xl→60px、rounded-2xl→16、py-24→96）。
- 区块识别顺序：页脚 → id/class 里的词（最准）→ h1/首段按钮 → 结构特征（两个以上引用→评价、两个以上价格→价格表、表单→联系）→ 标题里的词。第二个“首屏”记成内容区。
- 喂料（corpus.py）：文件夹 / .html / .zip（只解 html/css/scss，拒绝 ../ 和绝对路径，限大小数量）/ GitHub 仓库（clone --depth 1 到一次性目录，禁钩子、不拉子模块、不装依赖，读完就删）/ 网址（只取 HTML 和同站 CSS，遵守 robots.txt，拒绝内网地址和跳转到内网，限时限大小）。按内容和来源去重；按来源撤回。
- 自我纠错：某个网站读出错 → 这一个跳过、错误记进 corpus/errors.jsonl，不打断整批；提取器改进后 `--refresh` 把所有来源重读一遍，结论跟着改。
- 来源清单里猜错的仓库（不存在）会被跳过并写明“仓库不存在或不公开”，不会编造。

## 反例（什么时候不适用）
- 用 React/Astro/Vue 写、没有编译好 HTML 的模板读不出版面（会跳过“里面没找到网页”）；要学它们得先有构建好的页面。
- 只读静态结构：靠脚本动态生成的版面看不到（这是故意的——不运行脚本）。
