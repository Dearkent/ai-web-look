## 根因
VibeSDK 蓝图里布局、设计、用户路径都是自由文本，下游 Agent 只能“理解”，检查脚本无从验证；风格枚举只有 6 个，表达力又不够。

## 做法
- 布局变体、区块类型、动效类别与档位、风格、落地页模式、Agent 全部是封闭词表；词表由知识库生成，不手写。
- 跳转、素材、功能、数据实体一律按 ID 引用，检查器逐条验证引用存在。
- 每个推断字段带来源（user / inferred / default / kb）和置信度，学习回路据此统计默认值被改的比例。
- 区块树与 Puck 同构，生成后可直接拖拽编辑。

## 反例（什么时候不适用）
文案内容本身、给文案 Agent 的说明不该封闭。
