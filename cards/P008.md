## 根因
多个 Agent 同时改同一个文件、或一边写文件一边提交，会互相覆盖；全部串行又太慢。

## 做法
- 动作参数类型里直接算出资源：读/写哪些文件、是否 git 提交、对沙箱做什么操作。
- 冲突规则保持简单：同一文件有写就冲突；沙箱执行/分析/部署互斥，只读可并行；规划操作互斥；提交与写文件冲突。
- 调度器把不冲突的动作并行执行，冲突的排队。
- 我们的分工天然适合：文案 Agent、动效 Agent、图片 Agent 写不同文件，可以并行。

## 反例（什么时候不适用）
资源声明由模型自报时不可信，必须从参数里由代码算出，不能让模型自己填“我会改哪些文件”。
